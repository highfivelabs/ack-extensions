# Contributing to ack-extensions

Thank you for helping fill the gaps in AWS Controllers for Kubernetes
(ACK). This page says how changes are signed off, how to test them, and
the rule that shapes most of the code.

## Sign off your commits

ack-extensions uses the [Developer Certificate of Origin](https://developercertificate.org/)
(DCO) instead of a contributor licence agreement. By signing off a commit
you certify that you wrote it, or otherwise have the right to submit it,
under the project's licence (Apache-2.0). Add the line with `git commit -s`:

```text
Signed-off-by: Your Name <you@example.com>
```

## Build and test

Everything runs against a fake AWS (moto in server mode); no AWS account
or credentials are needed, and tests must never use them.

The commands are tasks in `Taskfile.yml`, run with
[Task](https://taskfile.dev) 3.54 or later (`brew install go-task`, or
`go install github.com/go-task/task/v3/cmd/task@latest`); `task` lists them.
The tasks any Go repository could use (installing a pinned tool, gofmt
and generated-output checks, envtest) are factory's `taskfiles/go.yml`,
included remotely at a tag and checksum and fetched with your git
credentials on the first run (factory `taskfiles/README.md`). Every directory under `services/`
is a service, so adding one needs no edit to the Taskfile.

```sh
task tools         # once: the pinned generator, controller-gen, goimports, setup-envtest, moto
task check         # generated files current, gofmt, vet, SPDX lines, build, unit and end-to-end tests
task operator-e2e  # the operator on kind, beside ACK's real rds-controller, against moto in the cluster
task coverage      # regenerate docs/coverage/ and the README's Coverage section (commit the result)
```

A new or changed kind changes the coverage numbers: run `task coverage`
(`task coverage:check` fails if the committed outputs are stale).

Each kind needs an end-to-end test in `tests/e2e` on `pkg/test/harness`
(a real kube-apiserver, the service's real controller binary, and moto)
covering create, update or the refusal of an update, delete, and
`services.k8s.aws/deletion-policy: retain` where deletion has an effect.
If moto lacks the API or behaves differently from AWS, say so in the test
and in `docs/plan.md`.

Generated files carry `Code generated by ack-generate. DO NOT EDIT.` (or
controller-gen's equivalent) and come from `hack/generate.sh`; commit its
output. New Go files and shell scripts start with:

```go
// Copyright <year> <you or your employer>
// SPDX-License-Identifier: Apache-2.0
```

## The copy-upstream rule

Where ACK already has the resource or field, on `main` or in an open pull
request, copy its code and change as little as possible:

- Generate what ACK generates, with ACK's generator and the generator
  configuration and hook templates from upstream (`services/<svc>/`).
- Keep a copied file's copyright and licence header, and add a
  "Modified by High Five Labs for ack-extensions" note naming the source
  file and what changed. Record it in `UPSTREAM.md`.
- Never fork ACK's runtime or controllers: they are Go modules at the
  versions `go.mod` pins.
- When upstream ships the kind or field, retire ours (`docs/plan.md`,
  "Retiring a kind").
